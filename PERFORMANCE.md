# ACL: проверка обработки и ресурсов

## Что исправлено

- Перетаскивание увеличенного видео без лишних обновлений React.
- Быстрая проверка FFmpeg, Python и зависимостей перед обработкой.
- Единственный активный нейросетевой процесс на один Python-бэкенд.
- Атомарная фиксация WAV после успешного копирования.
- Реальное применение профилей постобработки к настройкам.
- Освобождение выданных локальных URL и отмена незавершённых waveform-задач.
- Пакетное накопление пиков, ограничение размера canvas и оптимизация рендеринга настроек.
- Обработка аварийного завершения Python и таймауты быстрых IPC-команд.

## Тест реальной нейросети

Команды запускаются вручную на компьютере с установленными зависимостями и моделями.

Windows:

    cd <папка-ACL>
    .\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
    .\.venv\Scripts\python.exe -m backend.smoke "C:\video\sample.mkv" --seconds 8

macOS/Linux:

    ./.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
    ./.venv/bin/python -m backend.smoke '/path/to/video.mkv' --seconds 8

backend.smoke вызывает настоящий нейросетевой движок на восьмисекундном фрагменте и проверяет выходной WAV. Отсутствующие модели могут скачиваться.

## Диагностика памяти

В DevTools приложения: await window.acl.diagnostics()

Поля: registeredMedia (активные файловые URL), pendingIpcRequests (незавершённые запросы), electronMemory, processes.

Сценарий: заменить видео 20 раз, выполнить несколько обработок с отменой,
сравнить число файловых URL, активных Python-процессов, RAM и VRAM до и
после периодов бездействия. Кеши Chromium/PyTorch не равнозначны утечкам.

## Ограничения

Сейчас не подтверждены работа реальных моделей и динамика RAM/VRAM под нагрузкой.
Синтаксис JavaScript проверен; сборка TypeScript и интеграционные Python-тесты
ожидают разрешения на запуск команд на удалённом компьютере.

## Изоляция нейросетевой обработки (октябрь 2026)

Очистка больше не импортирует `processor.py` внутри потока IPC-сервера. `backend/processing.py` запускает `python -u -m backend.processing_worker` и читает JSONL-сообщения `log`, `progress`, `error`, `done`. Модель загружается только в worker, который завершается после задачи и освобождает занимаемую память. Если worker не пишет новых сообщений, родитель раз в ~20 секунд выводит предупреждение. Дочерний worker также сообщает об ожидании текущей стадии каждые 15 секунд.

На Windows для отмены используется `taskkill /T /F`; на macOS/Linux сначала отправляется SIGTERM и даётся время на завершение, затем используется SIGKILL. После запуска новой версии полностью остановите Electron и снова выполните `npm run dev`, чтобы перезапустить IPC-бэкенд.

Проверки: `.venv/Scripts/python.exe -m unittest discover -s tests -p "test_*.py" -v` (Windows) или `.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v` (macOS/Linux). Полная AI-проверка по-прежнему проводится через `python -m backend.smoke ... --seconds 8`.
